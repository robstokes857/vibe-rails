# TokenSaver — findings, proofs, and how to make it better (2026-09-03)

Written for Rob after the Claude-first mining sweep. Everything here is measured on the 37 days
of proxied traffic in `~/.vibe_rails/proxy_exchanges.db` (2026-07-29 → 09-03, 49,750 rows,
45 GB), and every number can be regenerated with the commands in §5. The formal proposal with
per-item Status lines is [`plans/plan_1B.md`](plans/plan_1B.md); this file is the readable
version with the proofs spelled out and the suggestions ranked.

**The short version.** TokenSaver is doing what it was built to do, and for Claude that is
almost nothing: it removes 0.65% of the request bytes, and the one stage that removes most of
that (`truncate-long`) costs about three times what it saves because the model goes back for the
missing lines. Meanwhile 21% of every Claude request is tool definitions, 46% of which were never
called once in 37 days, and 10% of Claude spend is the auto-mode security classifier. The biggest
wins are configuration, not compression. Codex is the opposite story: the saver removes 8.5% of
its bytes and truncation pays for itself there.

Cost is stated in **cost-equivalent tokens** from the real `usage` blocks in every response:
Claude `uncached×1 + cache-write×1.25 + cache-read×0.1 + output×5`, Codex `(input−cached)×1 +
cached×0.1 + output×8`. Chars→tokens at 3.6 (calibrated on 222 full-tokenization turns).
"Per day" divides by the 34 (Claude) or 37 (Codex) days with traffic.

## 2. Findings and proofs

### F1. Where Claude's money goes: 55% cache reads

| | Claude | Codex |
|---|---|---|
| successful requests | 11,618 | 17,602 |
| uncached input | 3.94M | 84.3M |
| cache writes | 71.17M | — |
| cache reads | 1,794.8M | 1,762.8M |
| output | 11.27M | 7.8M |
| cost-eq total / per day | 328.7M / 9.67M | 323.0M / 8.73M |
| cost-eq shares | reads 55% · writes 27% · output 17% · uncached 1% | cached 55% · uncached 26% · output 19% |

**Proof.** `scan_conversations.py` parses `input_tokens` / `cache_creation_input_tokens` /
`cache_read_input_tokens` / `output_tokens` out of every stored `ResponseBody`; `timeline_stats.py`
section A sums them per day. Consequence: the "wire-weighted" view the runbook asks for is the
right one for Claude, discounted 10× — a byte that stays in a long conversation is re-read at 0.1
every turn for the rest of the session. The "unique" view is what the 1.25× cache write costs.

### F2. What a Claude request is made of

9,352 main-conversation requests, 6,276 MB, char-weighted:

| slice | share | can the saver touch it? |
|---|---|---|
| tool definitions | **21.2%** | no |
| tool results, all | 21.3% | |
| · allowlisted shell (Bash/PowerShell) | 9.3% | **yes — this is the entire pipeline's domain** |
| · `Read` | ≈10% | no (owner decision, and see F8: nothing there anyway) |
| thinking blocks | 13.4% | no |
| tool_use inputs (Write/Edit payloads) | 7.7% | no |
| assistant / user / system text | 8.7% | no |
| removed by the saver | **0.65%** | |

**Proof.** `timeline_stats.py` section C over `Requests`. Thinking is billed: Claude Code sends
`context_management: clear_thinking_20251015, keep: all`, and including thinking chars tightens
the chars-per-token fit (CV 0.45 vs 0.52 without). So 13.4% of every turn's cache read is the
model's own past reasoning, kept by the CLI's choice.

Drive 6 / 4.5 KB. Across the window the average request carries 142 KB / 59 tools; sessions range
from 30 tools / 85 KB to 69 / 175 KB, so the list is already configurable per session.

Tools present in that request that were **never called in 37 days** (all Claude conversations):

|---|---|
| 26,991 | Artifact |
| 9,204 | DesignSync |
| 4,728 | EndConversation |
| 4,643 | SendMessage |
| 4,034 | EnterWorktree |
| 3,754 | RemoteTrigger |
| 3,650 | CronCreate |
| 2,531 | ExitWorktree |
| 1,669 | NotebookEdit |

Called once: SendFeedback (5.6 KB), ReportFindings, PushNotification. Most-called: Bash 6,281,

### F4. The auto-mode security classifier is 10% of Claude spend

| class | requests | cost-eq | per call |
|---|---|---|---|
| `claude-sonnet-5`, no tools, 125 KB system prompt ("You are a security monitor for autonomous AI coding agents") | 2,160 (18.6% of Claude requests) | **32.0M (9.7%)** | ≈82k cache-read + ≈5k cache-write tokens |

**Proof.** `timeline_stats.py` section B splits requests by model × tools-present × system-prompt
size; the class is unmistakable. Each call re-reads the 125 KB prompt from cache and writes the
tool call being judged. Whether a permission allow rule skips the classifier for that command is
the unverified part (§3.1).

### F5. `truncate-long` costs Claude ≈3× what it saves

Method: for every result that carried `[... N lines elided ...]`, the saving is charged at
1.25 (write) + 0.1 per remaining resend; a **re-run** is any tool call in the very next
assistant turn that re-fetches the same artifact (same command; same shell tool with a shared
path token and a re-fetch head like `sed`/`head`/`git`/`grep`; a `Read` of a file named in the
elided command; or `pause_token_saver`), charged as one extra turn at that conversation's real
average turn cost plus the re-fetched output.

| provider / family | elisions | re-runs | saved cost-eq | re-run cost-eq | **net** |
|---|---|---|---|---|---|
| Claude · file dump (cat/sed/for …) | 78 | 58 (74%) | 951 K | 4,276 K | **−3,325 K** |
| Claude · git diff/show/log | 34 | 27 (79%) | 331 K | 921 K | **−590 K** |
| **Claude · all** | **114** | **86 (75%)** | 1,290 K | 5,222 K | **−3,932 K** |
| Codex · file dump | 288 | 95 (33%) | 11,833 K | 3,567 K | +8,266 K |
| Codex · git diff/show/log | 92 | 28 (30%) | 3,405 K | 1,128 K | +2,277 K |
| Codex · grep | 68 | 2 (3%) | 2,840 K | 117 K | +2,723 K |
| **Codex · all** | **593** | **161 (27%)** | 25,494 K | 7,389 K | **+18,105 K** |

Break-even on Claude is a 19% re-run rate. A deliberately strict classifier (exact command or
two shared tokens) still found 40% and a net of −3.3M. The model's own words in 11% of cases
remove any doubt about causation:

- `git diff -- src/backend-manager.ts` → 153 lines elided → *"153 lines were elided. Let me read
  the full backend-manager diff"* → `git diff -U2 -- … | sed -n '150,340p'`
- `git diff -- wwwroot/style.css` → 140 lines elided → *"Part of the style.css diff was elided.
  Let me read the full diff from a file"* → writes the diff to a temp file, then `Read`s it —
  the elision saved nothing and bought an extra turn plus an uncompressed copy
- `cat TokenSaver/Shape/CommandShape.cs` → 233 lines elided → `Read` with offset 150 (the
  2026-08-29 investigation biting itself)

**Why Claude and Codex differ.** Claude Code caps every Bash result at 30,000 chars before the
proxy sees it (max observed 29,307; the CLI's own `… [N characters truncated] …` note appears in
3 outputs), so on Claude the stage never does catastrophic-payload defence — it only trims 4–30 KB
outputs the model explicitly asked for. Codex exec output is uncapped (40 KB `Get-Content -Raw`
dumps are routine). A Claude turn is ≈5× dearer (Opus/Fable, 132 messages average, output at 5×).
And Claude goes back for what it lost (75–79%); Codex mostly doesn't (27–33%).

35 MB of the 41 MB of wire the saver "saved" on Claude was this stage. **The Claude savings
meter has been reporting a loss as a win.** Since the 2026-08-29 file-read widening, the
remaining Claude trigger is `git diff`/`show`/`log` — 79% re-run rate, still net-negative.

**Proof.** `rerun_economics.py --provider anthropic` / `openai` (report + examples), over
`Conversations` from `scan_conversations.py`.

### F6. Cache misses: TokenSaver is innocent; the causes are named

285 Claude requests re-wrote more than 50k cache tokens at once — **35.4M of the 71.2M cache-write
tokens (50%), ≈44M cost-eq, 13% of Claude spend.**

| cause | misses | tokens | avoidable? |
|---|---|---|---|
| first request of a conversation (resume, subagent, post-compaction) | 109 | 8.7M | no |
| 1-hour TTL expiry (idle > 1 h; `cache_control.ttl = "1h"` confirmed) | 58 | 13.6M | no |
| within 5 min of the previous turn — diffed byte-for-byte: | 64 | 7.3M | partly |
| · tools list changed (MCP server dropped/returned, connectors appearing late, dynamic `Bash`/`WebFetch` descriptions) | ≈32 | | **yes** (#5, #2) |
| · model switched mid-conversation | 10 | ≈1M | **yes** (#6) |
| · prefix-stable: server-side or CLI-side | ≈17 | | no |

The expensive blip: `claude-in-chrome` vanished and returned 32 s later → tools 67→38→71 →
262k + 277k cache-write tokens ≈ **675k cost-eq from one disconnect.** viberails-mcp vanishing
on a dev-instance restart: 155k. Google connectors appearing late: 3 × 65–96k.

**TokenSaver exonerated, by construction of the test:** for each of the 64 close-in-time misses
the original and the upstream bodies were compared to their predecessors; in every case the
upstream body diverged at exactly the point the original did (a moved `cache_control`, a changed
`tools[]`, a changed `model`) and never at a differently-compressed tool_result. Determinism holds
on live traffic.

Health otherwise: on mature turns (≥10 messages) 92% of Opus-5 and 80% of Fable-5 turns have a
<5% miss ratio.

### F7. The shell pipeline is at its ceiling on Claude

Bash output is 582 MB wire / 15.6 MB unique. By command (leading `cd X &&` stripped): `sed` 26%,
`cat` 16%, `grep` 15%, `git diff` 14%, `echo` 6%, `for` 3%, `ls` 3%, `git show` 2%. **41% is file
contents read through the shell** (the auto-mode harness tells the agent to read with `sed -n` /
`cat`), which the 2026-08-29 fix now keeps whole on purpose. The largest size bucket — 4–16 KB
outputs of 50–200 lines, 178 MB, 31% of Bash — is below every lossy threshold by design and is
exactly what the model asked for. Control characters are a non-issue (1,089 of 1,149 ctl-bearing
outputs are CRLF-only, handled by `crlf-normalize`; ESC in 35). Shape stages are irrelevant on
Claude: 84 recognized greps all-time, 4.6 MB wire.

Lossless stages on file content: Edit failures run 1.3% overall, 1/28 after a shell dump the
saver changed, 1/103 after an untouched one, 3/433 after `Read`. No signal, small n — which is why
#10 is hardening, not a bug fix.

### F9. Codex

10.7 GB of request wire: tool results 53% (code-mode `exec` 5,478 MB wire), encrypted reasoning
17%, developer/user text 11%, tool inputs 5%. Cache hit 95.4%. Passthrough was 100% from 8/1 to
8/16 (code-mode only, `exec` not yet allowlisted), 2–10% since plan_1A deployed 8/17–18. The saver
removes 8.5% of wire ≈ 25M cost-eq (7.8% of Codex spend). Whole-request savings fell from 15–28%
per day to 6–9% after the 2026-08-29 file-read widening: that widening gave up ≈8.3M net cost-eq
on Codex (its file-dump elisions were net-positive at a 33% re-run rate). The other 67% of the
time Codex went on without the middle of a file it had asked for — the correctness case the fix
was made for, so no reversal is suggested.

`ansi-strip` sized for Codex: the condenser fails open whole-string on any ESC, so 590 ESC-bearing
exec outputs never see dedupe/truncate. Stripping SGR/OSC/BEL then running the curated stages:
**1.62 MB unique / 43.6 MB wire (≈1.2M cost-eq), invariants OK.** On Claude the same candidate
fires 32 times for 0.5 MB — hence Codex-only.

## 3. The suggestions in detail

### 3.1 Claude Code configuration (Rob's side, biggest and cheapest)

**#1 Deny the tools you never use.** The 34 never-called definitions in F3 are 46% of the slice.
The mechanism to verify: put deny rules (`permissions.deny`) for Artifact, DesignSync,
EndConversation, SendMessage, EnterWorktree/ExitWorktree, RemoteTrigger, Cron*, NotebookEdit,
ListAgents into `.claude/settings.json`, start a session, run one turn, then
`python scan_conversations.py --name check && python timeline_stats.py --name check` and compare
`NumToolsDef` / `ToolsDefChars` of the new request against the 68 / 181 KB baseline. If the deny
rule only blocks use but the definition still ships, the number will not move and this item dies;
that one-turn test settles it. Note the built-ins are Anthropic's descriptions — nothing to trim
inside them.

**#2 MCP per project.** `claude-in-chrome` (22 tools, 27 KB, 12 of them never called) only earns
its place in sessions that drive a browser; the three Google connectors (6 auth-only tools, never
called) probably nowhere in this repo. Scope them in `.mcp.json` per project, or disconnect
before starting a long coding session. Sessions in the data already run at 30 tools / 85 KB, so
the configuration exists.

**#3 Classifier calls.** Run `/fewer-permission-prompts` (it mines transcripts for routine
read-only commands and writes allow rules). Then watch `timeline_stats.py` section B: the
`claude-sonnet-5 / no-tools / >100K` row per day is the classifier count. If allow-listed commands
skip the classifier, that row drops and each avoided call is ≈15k cost-eq.

**#6 Model switches.** Ten mid-conversation switches each re-wrote the whole context (≈100k
tokens at 1.25). Pick the model before the long session, or accept the cost knowingly.

### 3.2 TokenSaver changes

**Per-provider stage defaults (the mechanism behind #4 and #7).** Today one `CompressionPlan`
serves all providers (`LlmProxySettings.TokenSaverPlan`, resolved once in
`LlmProxySettingsService.Resolve` from `CompressionCatalog.Resolve(TokenSaverStageOverride)`).
Add an `OffByDefaultFor` provider list to `CompressionStageInfo`, make `Resolve(selection,
provider)` honour it, and give each rewriter its provider's plan. `TokenSaverStageOverride` keeps
its meaning (an explicit list replaces the curated set wholesale, all providers). Captures then
record honest per-provider `EnabledIds`. Wire-format ids untouched; the `CuratedDefaults_*` pins
get a per-provider variant; README stage table gains a column.

**#4 `truncate-long` off for Anthropic.** With the mechanism above it is one catalog entry. The
narrower alternative — treat `git diff`/`show`/`log` as file reads in
`CommandShapes.ReadsFileContents` for all providers — fixes 34 of Claude's 114 elisions but costs
Codex ≈2.3M net, so the provider-specific form is the one the data supports. After deploy,
`rerun_economics.py --provider anthropic` on fresh conversations must show zero elisions, and the
Claude savings tally will fall ≈85%. That is the correct outcome; it was counting a loss.

**#7 `ansi-strip` on for Codex.** Same mechanism, opposite direction: `OnByDefaultFor:
["openai"]`. The owner preference against rewriting terminal-shaped output was about Claude's
shell tabs; on Claude it would fire 32 times for nothing, so it stays off there.

**#8 An honest meter.** The tally counts `BytesBefore − BytesAfter` per request, so the same
elision is counted every turn and a net-negative stage shows as the biggest win. The proxy
already sees the response usage; it can attribute savings the way this report does: first
sighting of a rewritten result at 1.25, each resend at 0.1, per provider, and — because the next
request shows whether the model re-fetched — subtract re-run turns using the same classifier as
`rerun_economics.py`. Display "cost-equivalent tokens saved, net" and keep raw bytes as the
secondary number. This is what stops the next stage from being judged by the wrong number.

**#10 Verbatim file content.** `ReadsFileContents` currently widens the truncation budget; make
it also skip the lossless stages for that payload. The lossless stages saved ≈1 MB unique on all
of Claude's Bash output; on file dumps specifically the number is noise, and trailing-whitespace /
blank-run edits are exactly the kind of change that can make a copied `old_string` miss. Zero
measured harm so far (1/28), zero measured value either — pick correctness.

### 3.3 VibeRails product

**#5 MCP endpoint availability.** The MCP server lives inside the root `vb.exe`, so every
dev-instance restart makes every open Claude session drop viberails-mcp's tools and re-add them
later — two full cache re-writes per restart per session (F6). Options: keep the MCP endpoint in
a process that survives dev-instance restarts; or have the daemon/VS Code side hold the port and
proxy to the live backend; or at minimum surface the event (#9). `claude-in-chrome` blips are
Chrome's, but the dashboard can still show them.

**#9 Cache-miss attribution.** The proxy has both consecutive request bodies and the usage.
When `cache_creation_input_tokens` jumps above, say, 50k while the conversation key is unchanged,
diff `tools[]`, `model`, and the message prefix against the previous request and log one line:
*"turn re-wrote 262k tokens: tools list changed (claude-in-chrome disconnected)"*. Cheap, and it
turns a 13%-of-spend line item into something Rob sees the moment it happens.

**Ops note, not savings.** `proxy_exchanges.db` grows ≈1.5 GB/day (45 GB now). The runbook's
"no retention by design" is fine while disk lasts; full passes are cheap (2–4 min), so a 60-day
window would lose nothing this analysis needs.

### 3.4 What not to do

Don't flip `scope-read` on for savings (F8: 0.24%). Don't add shape recognizers for piped
commands (F8: 3 outputs). Don't make truncation more aggressive on Claude (F5). Don't compress
thinking, tool inputs, or definitions in the proxy (F8: charter, and cache stability). Don't try
age-based or history-dependent rewrites (README: cache thrash by construction; F6 shows what a
single prefix break costs).

### 3.5 Our own MCP server (trimmed after Rob's follow-up, 2026-09-04)

**Decision (Rob, 2026-09-04):** make the MCP server static; leave tool calling to Claude Code.
Lazy tool-definition loading through a prompt-injected hook, `vb mcp list/call` through Bash,
and an MCP gateway were considered against the Recursive Language Models post
(alexzhang13.github.io/blog/2025/rlm) and **dropped**: the model is trained on its native tool
surface, and a half-way replacement of it would cost more than it saves. Do not re-propose.
The one RLM-shaped idea worth remembering is a `vb ask` context oracle for orientation reads
(41% of Claude's shell output is file dumps), but Claude Code's Explore agent already is that
pattern and the estimated ceiling is ≈0.6% of spend — parked.

**What the data says about viberails-mcp.** Six tools, 3.3 KB of definitions (1.8% of the
definition slice, ≈0.26% of spend if it vanished); four of the six were never called in 37 days.
Its bytes are not the lever. **Its lifetime is:** the server lives inside the root `vb.exe`, so a
dev-instance restart makes every open Claude session drop its tools and re-add them when the
backend returns — two full cache re-writes per restart per session (F6: 155k tokens for one
drop; the equivalent `claude-in-chrome` blip cost 262k + 277k). Native tool deferral
(`ToolSearch`) is not active in any sampled session.

**The MCP changes that stay (ranked-list #5):**

- **Decouple `/mcp`'s lifetime from the dev instance.** Serve it from the daemon, or put a stable
  front in place that answers `tools/list` from a static manifest and forwards `tools/call` to
  whichever backend is alive (clean tool error while it restarts). Claude Code's tool list then
  never changes mid-session — the only MCP change with a measurable payoff.
- **Session-stable, static descriptions, tested.** A test that two `tools/list` calls are
  byte-identical; never embed dynamic text in a description (Claude Code's own `Bash`/`WebFetch`
  descriptions changed mid-session 3 × ≈90k tokens). Ours are static today; keep it so.
- **Optional trim:** fold pause/resume/status into one `token_saver(action)` tool (three
  definitions → one, −1.1 KB); `python_script_signing_help` is documentation, not a tool. If B1
  (#4) lands, the pause hatch is moot for Claude anyway; it was never used in 37 days.

## 5. Reproduce

```
cd python-scripts/token_saver
python build_corpus.py --name <you>                       # incremental corpus
python scan_conversations.py --name <you>                 # incremental sequence dataset
python timeline_stats.py --name <you> --provider anthropic   # F1, F2, F4, F6 health, reactions
python rerun_economics.py --name <you> --provider anthropic  # F5 (also --provider openai)
python corpus_stats.py --name <you>                       # F7 tables
python experiment.py candidates/read_minify_only.py --name <you> --provider anthropic --tool Read --on raw
python experiment.py candidates/ansi_strip_then_curated.py --name <you> --provider openai --tool exec --on raw
```

Tool-definition itemization (F3): pick a request via `Requests.ToolsDefChars`, then
`json.loads(RequestBefore)["tools"]`; calls per tool come from the `Conversations` timelines.
Cache-miss forensics (F6): for each request with `CacheCreationTokens > 50000` and a same-
`ConvKey` predecessor within 5 minutes, compare `system`/`tools`/`model`/`messages[:-2]` of the
two upstream bodies. Both are ~40 lines against `mining_timeline.db` and are worth re-deriving
rather than maintaining. All reads are `mode=ro`; nothing here leaves the machine.
